# Чёрный ящик

## Суть задачи

Шифртекст `flag XOR 0xD2` пришит в код в виде четырёх 64-битных констант,
которые при запуске складываются на стек («stack string» — так малварь прячет
строки от `strings`). Из-за этого статический поиск по строкам и `.rodata`
молчит, а декомпилятор показывает всё как на ладони. Задача полностью решается
в браузере: dogbolt.org + CyberChef, без Python и без установки инструментов.

## Решение

### Путь 1 (основной, «браузерный»): dogbolt + CyberChef

**Шаг 1.** Загружаем `crackme` на <https://dogbolt.org/>, смотрим псевдокод
`main` (вывод ниже — реальный от IDA в dogbolt; Ghidra/Binary Ninja покажут
то же самое в другой нотации):

```c
*(_QWORD *)s2 = 0xA2A1B4B9A1BFBDA6LL;      // buf[0..7]  = шифртекст, LE
v6 = 0x8DA1BB8DA0BDAAA9LL;                 // buf[8..15]
v7 = 0xA0B1BCB78DA6BDBCLL;                 // buf[16..23]
v8 = 0xD2AFBCBDBBA6A2ABLL;                 // buf[24..31], последний байт - padding
for ( i = 0; i < 0x1F; ++i )               // 0x1F = 31 = длина флага
  s2[i] ^= 0xD2u;                          // ключ XOR виден прямо в цикле
HIBYTE(v8) = 0;                            // buf[31] = '\0' - терминатор строки
...
if ( strcmp(argv[1], s2) == 0 )            // сравнение с вашим вводом
```

**Шаг 2.** Рецепт CyberChef (4 операции):

| # | Операция | Аргументы | Зачем |
|---|---|---|---|
| 1 | Find / Replace | `0x` → `` (без regex) | убрать префиксы |
| 2 | From Hex | Delimiter: None | константы → байты |
| 3 | Swap Endianness | Word length: 8 | x86 хранит константы little-endian, байты «перевёрнуты» |
| 4 | XOR | Key: `d2`, scheme: Standard | снять шифр |

На вход — четыре 16-значных значения (после `0x`), склеенные по порядку:

```
a2a1b4b9a1bfbda68da1bb8da0bdaaa9a0b1bcb78da6bdbcd2afbcbdbba6a2ab
```

На выходе — флаг; завершающий `\x00` после `}` — это терминатор строки
(последняя константа пришита с байтом-заполнителем, равным ключу XOR).

**Шаг 3.** Проверка: `./crackme 'tomskfsp{...}'` → `ACCESS GRANTED`.

### Путь 2 (Linux-утилиты): objdump + CyberChef

Тот же вход для CyberChef дают локальные утилиты — константы видно прямо
в дизасемблере:

```bash
objdump -d crackme | grep movabs
# 11d3: 48 b9 a6 bd bf a1 b9 ...  movabs $0xa2a1b4b9a1bfbda6,%rcx
# ...
```

`.rodata` шифртекст больше не содержит — не тратьте время на
`objdump -s -j .rodata`.

### Путь 3 (динамика): ltrace / gdb

```bash
ltrace ./crackme test123 2>&1 | grep strcmp
# strcmp("test123", "tomskfsp{...}") = -1
```

или breakpoint на `strcmp` в gdb, затем `x/s $rsi`.

> **Флаг:** `tomskfsp{xor_is_not_encryption}`

## Вывод для студентов

- **Stack strings** — базовый приём скрытия строк в малвари: вместо
  «строки в .rodata» байты загружаются на стек инструкциями `movabs`,
  и `strings` ничего не видит. Противоядие — декомпилятор: константы
  и ключ XOR читаются в псевдокоде напрямую.
- XOR с константой — не шифрование: ключ всегда лежит рядом, в том же коде.
- Порядок байт — часть задачи: 64-битная константа в x86 хранится
  little-endian, поэтому в псевдокоде байты «перевёрнуты» внутри каждой
  восьмёрки (CyberChef `Swap Endianness` именно это и чинит).
